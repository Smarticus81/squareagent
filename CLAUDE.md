## Project Overview

VoyceLab — a voice-ordering platform that connects to Square POS. Users speak orders through a voice agent (browser PWA or Expo native app), which uses OpenAI's Realtime API via WebRTC, and syncs orders live to Square.

## Monorepo Structure

pnpm workspace (Node 22, TypeScript 5.9, pnpm 9.15.9) with two package directories:

- **`lib/`** — shared libraries consumed by artifacts
  - `db` — Drizzle ORM + PostgreSQL schema (users, venues, subscriptions, sessions, exchange_codes, voice_sessions). Run `pnpm push` inside this package to migrate.
  - `api-zod` — Zod validation schemas generated by Orval from OpenAPI spec
  - `api-client-react` — TanStack React Query wrapper (scaffolded, not yet implemented)

- **`artifacts/`** — deployable applications
  - `api-server` — Express 5 backend: REST API, WebSocket relay, serves both frontends as static files in production. Imports `@workspace/db` and `@workspace/api-zod`.
  - `voice-agent-pwa` — React + Vite PWA for browser-based voice ordering via WebRTC
  - `voycelab-landing` — React + Vite + Tailwind + shadcn/ui dashboard (auth, venue management, account settings). Uses Wouter for routing.
  - `square-voice-agent` — Expo/React Native mobile app (Expo Router, react-native-webrtc)

## Commands

```bash
# Install dependencies
pnpm install

# Full build (typecheck + all artifacts)
pnpm build

# Typecheck only
pnpm typecheck

# Railway-specific build (sequential: typecheck → build landing → build PWA → build API)
pnpm build:railway

# Start production server
pnpm start

# Local dev (Windows) — starts API (8080), landing (5173), PWA (8081) in separate terminals
start-all.bat          # PWA mode
start-all.bat expo     # Expo mode instead of PWA

# Individual dev servers
cd artifacts/api-server && pnpm dev          # API on :8080
cd artifacts/voycelab-landing && pnpm dev    # Landing on :5173
cd artifacts/voice-agent-pwa && pnpm dev     # PWA on :8081
cd artifacts/square-voice-agent && pnpm dev  # Expo

# Database migration
cd lib/db && pnpm push
```

## Architecture

**Voice ordering flow**: Client (PWA/Expo) requests an ephemeral OpenAI token from `POST /api/realtime/session` → establishes WebRTC RTCPeerConnection directly to OpenAI Realtime API → user speaks → OpenAI transcribes and triggers tool calls → client POSTs tool execution to `POST /api/realtime/tools` → API server executes Square operations via `square-helpers.ts` → order synced to Square POS.

**Single-server deployment**: The API server serves the landing app at `/`, the PWA at `/agent/`, API routes at `/api/*`, and a WebSocket relay for the native Expo app. All deployed as one Railway service.

**Auth**: JWT-based. `requireAuth` and `requirePlan` middleware gate API routes. Stripe integration manages subscriptions (plan/trial gating).

**Square integration**: OAuth flow at `/api/square/oauth/*` stores tokens per-venue in the database. Live order operations go through `api-server/src/lib/square-helpers.ts`.

## Skills System

Tools are organized into composable **skills** (`api-server/src/skills/`), each bundling related tools with system prompt segments and subscription tier gating:

| Skill | Tier | Tools |
|-------|------|-------|
| `pos` | core | add_item, remove_item, get_order, clear_order, submit_order, send_to_terminal, search_menu |
| `orders-reporting` | core | list_orders, sales_report, list_open_orders, get_order_details, hourly_sales, item_performance, daily_summary, list_locations |
| `inventory` | standard | check_inventory, check_all_inventory, adjust_inventory, set_inventory, transfer_inventory, get_inventory_changes, low_stock_report, get_item_details, batch_adjust_inventory, inventory_summary |
| `catalog-management` | standard | create_item, update_item, delete_item, list_categories, create_category, list_modifiers, apply_discount |
| `customers-payments` | standard | search_customer, create_customer, get_customer, update_customer, list_payments, refund_payment, cancel_payment |
| `team-labor` | premium | list_team, current_shifts, clock_in, clock_out |

Sessions load only the skills matching the user's subscription plan (`getSkillsForSession(plan)`). System prompt is composed from skill instruction segments.

## Workflow Engine

Multi-step workflows (`api-server/src/workflows/`) orchestrate tool sequences and register as callable tools:

- `end_of_day_close` — daily_summary → list_open_orders → low_stock_report
- `opening_checklist` — inventory_summary → low_stock_report(10) → current_shifts → list_locations
- `stock_take` — check_all_inventory → inventory_summary

Add new workflows by creating a definition in `workflows/definitions/` and registering it in `workflows/index.ts`.

## Tool Middleware

All tool executors are wrapped with middleware (`api-server/src/tools/middleware.ts`):
- **errorMiddleware** — catches thrown errors, returns normalized ToolResult
- **timingMiddleware** — logs execution duration, warns on >2s
- **loggingMiddleware** — logs tool invocations with sanitized args

Custom middleware follows the `ToolMiddleware` signature: `(toolName, args, ctx, next) => Promise<ToolResult>`.

## Performance Layer

- **SquareClient** (`lib/square-client.ts`) — fetch wrapper with exponential backoff retry (3 attempts), circuit breaker per venue (opens after 5 failures in 60s)
- **Credential Cache** (`lib/credential-cache.ts`) — 5-min TTL in-memory cache for venue Square credentials, avoids DB hit on every tool call
- **Catalog Cache** (`lib/catalog-cache.ts`) — 5-min TTL per-venue catalog cache, avoids re-fetching from Square API
- **Session Store** (`lib/session-store.ts`) — in-memory + DB write-through for voice session state, survives server restarts

## Key Conventions

- Workspace packages use `"customConditions": ["workspace"]` in tsconfig for cross-package imports
- API server bundles to a single CJS file via esbuild (`artifacts/api-server/build.ts`)
- PWA builds with `BASE_PATH=/agent/` for production sub-path serving
- Database schema lives in `lib/db/src/schema/` using Drizzle table definitions
- Route handlers are in `artifacts/api-server/src/routes/` (auth, square, venues, realtime, openclaw, subscriptions)
- Tool domain modules are in `api-server/src/tools/` — each exports `definitions` and `executors`
- Skill modules are in `api-server/src/skills/` — each wraps tool modules with instructions and tier
- OpenClaw bridge (`routes/openclaw.ts`) delegates to shared `executeToolCall`, not inline logic
